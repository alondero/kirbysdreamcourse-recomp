## Method and coverage

saves/settings and physical inputs disabled. Desktop-control tools were not
available. Rendered screenshots were inspected locally; guest framebuffer
dumps alone omit host overlays and do not establish their appearance.
All ROM-derived captures, input recordings and saves remain under ignored
`local/`. The local harness and its case directories are
`local/playtest.py` and `local/playtest/` in this worktree.

Unless explicitly comparing a feature off, runs enabled widescreen, edge HUD,
HD textures, orbit controls and smooth presentation at 120 Hz. Functional
replays were unpaced; separate paced measurements exercise interpolation.
The timing flags match `tools/play_experimental.ps1`.

## Small fix

`play_experimental.ps1 -DevHole` previously copied only `config.ini` and
`keybinds.ini`. A fresh developer directory therefore lost all five game-owned
mod preferences even when they were enabled beside the source executable.
It now seeds missing `kdc-hd.cfg`, `kdc-presentation.cfg`, `kdc-hud.cfg`,
`kdc-widescreen.cfg` and `kdc-camera.cfg`, preserving existing developer choices.

A real one-frame developer launch reproduced the five missing files before
the fix. Afterward all five matched their source; a second launch preserved a
changed developer HD preference. The ROM-free PowerShell regression executes
the staging script with stubbed ROM validation and host invocation. It fails
against the original script on missing `kdc-hd.cfg` and passes after the fix.

## Performance finding

Filed [issue #67](https://github.com/alondero/kirbysdreamcourse-recomp/issues/67)
for substantial simulation slowdown with HD orbit and paced presentation.
Ryzen 9 3900X, default 12 rendering workers, SDL software renderer and dummy
video/audio drivers. These are host-side simulation/composition measurements,
not physical monitor-delivery measurements. The timed passes ran sequentially,
without competing playtest processes or screenshot writes.

The scenario starts at `multi-extra:3:1`, enables all presentation mods, holds
maximum right orbit and zoom-in from guest frame 500 through 649, then releases.
It runs 1,800 simulation frames with smooth presentation targeting 120 Hz.
Host profiling begins at frame 350. Local reproducer:
`local/performance_playtest.py`; controls: `local/performance-controls.log`.

| View | HD | Simulation fps, successive runs | Mean composition per present |
| --- | --- | --- | --- |
| 16:9 | on | 50.76 / 52.72 | 6.333 / 5.962 ms |
| 16:9 | off | 58.50 / 59.19 | 0.685 / 0.701 ms |
| 32:9 | on | 35.04 / 35.22 | 9.477 / 9.729 ms |
| 32:9 | off | 59.43 / 40.01 / 57.88 | 0.976 / 1.654 / 0.955 ms |

The anomalous second 32:9 HD-off control slowed across all stages: guest work
averaged 10.172 ms instead of approximately 6 ms. A third run restored similar
costs to the first. Host-load variation is a possible explanation, not an
isolated cause; all measurements are retained above.

The first 32:9 HD run took 51.374 seconds for 1,800 simulation frames while
producing 3,146 presentations. Later orbit-profile groups had no full terrain
rebuilds or scenery enlargements, but retained roughly 0.85–0.88 ms preparation
and 6.9–8.1 ms drawing per present. This is sustained work after warmup.
Animated terrain still triggers local tile rescaling. Worst composition in
the two HD runs was 42.981 / 32.014 ms without screenshot I/O.

Lowering the presentation target to 60 Hz did not restore simulation speed:
the same 32:9 HD case took 49.478 seconds (36.38 simulation fps), with mean
composition 9.163 ms. Investigation should separate renderer cost from
presentation scheduling and qualify a real display backend before choosing
a fix. This larger change was left out of the settings-copy fix.
An unpaced control also remained slow (36.73 simulation fps, composition
13.383 ms), so these measurements do not isolate a scheduling defect.
